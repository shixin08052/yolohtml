# v1.0.2–v1.0.3 优化与验证记录

日期：2026-11-09。

## 设备与格式约束

本演示指定使用 iPhone 13 Pro 主摄 1×、4:3。保留固定内参及原有可靠时自动估计焦距的行为，仅补充机型、焦距、裁剪比例和 EXIF 缺失警告；等比缩放不因分辨率变化而报警。

上传入口仅接受 JPEG、PNG；实际读取时同时检查文件头，拒绝 HEIC/HEIF（包含改名为 .jpg 的情况）及其他格式，不引入格式转换依赖。

## 验证方式

```bash
npm test
npm run build
npm run dev
```

开发服务器启动后打开 `http://localhost:5173/tests/browser.html`，点击“运行回归检查”。该页面不包含在生产构建中。

新增自动检查包括：指定设备与比例警告、实际上传格式、JSON 换图竞态、下载超时和取消、Worker 无响应及取消后重试、照片复制期间取消、流程图来源，以及 WebGL 初始化失败。

浏览器回归页覆盖真实入口中的合成演示、开始/暂停/重置、窄屏控制和折叠、演示确认来源、HEIC 改名拒绝、77 mm 警告，以及 WebGL 创建失败后继续识别照片。

本次本地验证：37 个测试文件、368 项测试全部通过，生产构建成功；390 × 844 视口下两组浏览器回归通过。真实示例 IMG_9899 验证了取消后重试，并完成分拣，消息为“10 个零件，拨开 4 次”。浏览器视口模拟不等同于实体 iPhone Safari 验证。

## 后续测量

- 指定设备 Safari 上的触摸、冷启动、峰值内存与慢网络表现仍需实机验证。
- 暂不更换模型、输入尺寸或图像缩放算法；先冻结指定设备上的独立测试集，评测完整流水线，再决定模型压缩和前处理内存优化。
- 大型入口按职责拆分作为后续维护任务，避免与本轮行为修正同时重构全部算法。

## v1.0.3 细节复查

本轮保留指定设备、固定内参与 JPEG/PNG 上传约束，修正以下边界行为：

- 分拣开始、暂停后继续时，立即报告当前步骤；开始分拣时结束尚在播放的照片转场。
- 重试会清除旧错误，读取新照片或重新识别期间禁止启动旧分拣场景。
- mock 文件失败后点击“改用 WASM”，同时将检测方式切换为 ONNX，避免再次请求同一个 mock 文件。
- 切换检测方式、手动改框或导入文件会取消旧任务；照片复制期间的取消也按用户取消处理。
- 手动结果和导入结果清除旧模型耗时、检测统计及尺寸修正记录；演示模式导入新结果后需重新确认。
- 示例列表、示例图片/真值、mock 检测文件均增加 30 秒下载截止时间；切图取消旧示例请求，任一配对资源失败时取消另一项；解码期间作废的 bitmap 会释放。
- 无 WebGL 时，演示模式仍能展示已填充的正视图；确认按钮改为“确认，查看照片”，返回可用的照片视图。

验证：38 个测试文件、375 项单元测试通过。390 × 844 视口下四组浏览器回归通过，新增覆盖 mock → WASM 恢复、旧错误清理、真实模型识别后手动改框/导入文件的统计清理，以及无 WebGL 的演示确认。实体 iPhone Safari 验证仍待完成。

## v1.1.0 界面与手机演示

日期：2026-11-10。

- **界面风格**：改为液态玻璃。底层是暖米色底加三块很淡的环境色（固定一层，只画一次）；照片和 3D 画面是不透明的内容层；顶栏、卡片、按钮是半透明玻璃（上亮下暗的渐变、顶部高光、柔和投影）。
- **性能约定**：`backdrop-filter` 实时模糊只用在真正盖在会动内容上的小块控件——画面上的工具条、正射图小窗、手机底部的分拣条、子页面的吸顶栏；其余玻璃面下面是静止底色，只用半透明渐变。3D 里的零件标签数量多且每帧移动，不用模糊。过渡只改 transform、opacity 和颜色。浏览器不支持模糊或系统要求降低透明度时换成近乎不透明的底。
- **正视图（演示模式确认页）**：新增缩放和平移（`src/ui/panZoom.js`）——双指捏合、滚轮、＋ − 按钮、双击放大 / 复位，最大 8 倍，放大后不能拖出空白。标签在屏幕上大小不变，窄屏整体小一号，整个框在画面外的零件不画标签，标签避开左上角的按钮。拖动时每帧最多重画一次，画布只在大小变化时重新分配。
- **手机布局**：视图区高度改为屏幕可见高度的 70%（原来确认栏换行后把正视图挤得只剩一小条）；顶栏三行（标题 / 上传与示例 / 步骤条）；开始分拣时滚到标签页处，3D 画面落在顶部和底部分拣条之间。
- **步骤条**：圆点和文字包进 `.pill`，当前步骤的高亮只罩住它，不再把前面的连接线也框进去；手机上只有当前步骤显示文字，六步铺满一行，不用横向滚动。
- **示例照片**：自带示例去掉了 EXIF，原来每次都提示“缺少机型信息”“缺少焦距信息”，演示时像出错。现在示例不提示，用户上传的照片照常核对；没有警告时只显示一行“当前内参”。

验证：39 个测试文件、382 项单元测试通过（新增缩放范围、缩放中心、标签大小与避让）；生产构建成功；390 × 844 与 1280 × 800 视口下四组浏览器回归通过；390 × 660 触屏模拟下用双指捏合放大正视图、确认、开始分拣，页面无报错。实体 iPhone 上的捏合手感和模糊性能仍需实机确认。

## v1.1.2 发布卡住的排查

日期：2026-11-10。

**现象**：v1.1.0 合并到 `main` 后，构建、测试、上传产物都成功，`actions/deploy-pages` 一直显示 `syncing_files`，10 分钟超时。重跑、重新完整运行、换一个提交（v1.1.1）都一样。GitHub 状态页正常。

**排查过程**（每一步都是合并到 `main` 后看发布结果，Pages 环境只允许 `main` 部署）：

| 步骤 | 内容 | 结果 |
| --- | --- | --- |
| 重跑昨天的 v1.0.3 运行 | 旧提交、旧内容 | 第一次查询就返回成功——沿用了已有的发布记录，不能说明问题 |
| PR #3 | v1.0.3 的内容 + 新提交 | 成功（5 秒）→ Pages 正常，卡住由 v1.1.x 的内容触发 |
| PR #4 | v1.1.1 的 HTML、JS + v1.0.3 的 CSS | 成功 → 触发点在新样式里 |
| PR #5 | 完整 v1.1.1，只把样式里的两处内嵌 SVG 箭头改为 CSS 画 | 成功 → 触发点是样式里的内嵌 SVG |

**结论**：去掉样式里的 `url("data:image/svg+xml,…")`（`theme.css` 的 `--chev`，浅色、深色各一处）后发布恢复正常，其余内容不变。为什么它会让 Pages 的文件同步卡住，没有查明——只有这一组对照，机制未知。

**处理**：下拉框箭头改用两块渐变拼出，折叠分区箭头改用边框画；样式里不再使用内嵌 SVG。

**教训**：
- 发布卡住时不要只凭“构建成功、状态页正常”就认定是平台问题，应尽早用“旧内容 + 新提交”做对照。
- 重跑一个已经发布成功过的提交不算对照：它会直接返回原来的成功记录。
