# 视觉分拣数字孪生系统

用 iPhone 拍一张照片：照片里是一张贴了 4 个 ArUco 码的 A4 底板，板上放着电阻和各色 LED。网页识别出零件，在 3D 里按真实尺寸重建桌面和零件，再由虚拟机械臂按类别（LED 按颜色）分拣进料盒。纯前端静态网页，不需要后端。

在线体验：<https://shixin08052.github.io/yolohtml/>（打印标定板：`board.html`；加 `?demo` 进入演示模式）

## 流程

1. **识别**：读取照片 → 识别 ArUco 码、求单应性 → 反推拍照时手机的位姿 → YOLO26n 检测零件（浏览器里 WebGPU / WASM 推理），颜色分割补漏，按 LED 的固定尺寸修正挤在一起时偏大的框
2. **定位**：检测框映射到底板毫米坐标（含视差修正）；看引脚定零件朝向，判断 LED 颜色
3. **执行**："照片 → 3D"转场；机械臂逆运动学规划，挤在一起的零件先拨开再夹，避开引脚；导出分拣指令（CSV / JSON）

## 使用

- 指定拍摄设备：iPhone 13 Pro 主摄 1×、4:3；上传仅支持 JPEG/PNG，不支持 HEIC/HEIF。机型、焦距或照片比例不符时会警告，固定内参策略保持不变。
- 打开页面，选示例照片或上传自己拍的照片（底板用 `board.html` 按 100% 打印）
- 普通模式：右侧信息面板显示每一步的参数、误差和耗时，可手动框选、导出流程图 / 零件图片 / 分拣指令
- 首页“一键看演示”：直接用一张实拍示例照片跑完整流程
- 元件清单：场景建好后列出板上每种元件的数量（可导出 CSV）；改“需要”的数量即按清单分拣，只拣要的，板上不够的标出缺几个；按实际夹爪遮挡数优先选择元件；挡路的拨开或夹起挪到板上空位，只有清单目标入盒，没有安全空位时报告跳过
- AI 帮我填清单：用一句话描述要做的电路，由大模型给出每种元件的数量。通过 DeepSeek Chat Completions API 接入（原生 `fetch`，浏览器直连；默认 `deepseek-flash`，地址 `https://api.deepseek.com/chat/completions`），在“接口设置”里填自己的 API Key（只保存在本机浏览器）
- 机械臂指令：分拣分区和结果卡上的“查看机械臂指令”列出每一步的抓取点、夹爪、关节角，与导出的 CSV / JSON 是同一份数据；分拣时控制条实时显示关节角
- 演示模式（顶栏按钮或地址加 `?demo`）：只显示流程图，识别后先给出正视图请确认，确认后再建模分拣

## 开发

```bash
npm install
npm run dev     # 本地开发
npm test        # 单元测试（vitest）
npm run build   # 构建到 dist/
npm run release:html # Windows：生成带双击启动脚本的 HTML 展示 ZIP（release/）
```

## Windows 展示包

`release/SortingTwin-v1.2.2-html-windows.zip` 是静态 HTML 发布包，不含 exe。完整解压后双击“启动展示.cmd”，会使用 Windows 自带 PowerShell/.NET 启动仅本机可访问的 HTTP 服务并打开演示页面；不需要安装 Node.js 或 Python。展示时保持启动窗口运行，结束后关闭窗口。

模型、WASM 和全部示例随包提供，识别、3D 和分拣可离线展示。DeepSeek 助手需要联网并配置自己的 API Key。浏览器对 `file://` 下的 Worker 和 WASM 有限制，请通过启动脚本打开，而不是直接双击 index.html；也可以将包中的网页部署到任意静态服务器。

打包脚本会校验各网页资源、模型和 WASM 的 HTTP 内容、MIME 和 SHA-256，并对 ZIP 解压后的中文/空格路径再次启动验证。输出目录附有 ZIP 的 `.sha256` 校验值和验收结果 JSON，包内附有使用说明及逐文件校验清单。

推送到 `main` 后由 GitHub Actions 测试、构建并部署到 GitHub Pages（`.github/workflows/pages.yml`）。

## 目录

- `src/vision/`：内参、ArUco、单应性、位姿、检测、坐标映射、引脚与颜色
- `src/robot/`：逆运动学、分拣规划、拨开、动作序列、指令导出（纯函数，有单元测试）
- `src/scene/`、`src/ui/`：Three.js 场景与界面
- `training/`：YOLO 训练（Colab）与报告；`tools/`：相机标定
- `docs/TASKS.md`：开发任务书与完整变更记录

### DeepSeek 清单接口与 token

- 设置支持根地址、`/v1` 或完整 `/chat/completions` 地址。模型名可在“接口设置”里修改；DeepSeek 的 Key/模型单独保存在 `yolohtml.deepseek`，不会沿用旧 Anthropic Key。
- 单轮请求只包含固定 system 提示和最多 500 字的需求，不发送库存、照片、坐标、运动路径或对话历史。库存缺口在本地计算。
- 思考强度提供“关闭 / 低 / 高 / 最高”，分别对应 `reasoning_effort: none/low/high/max`，默认关闭。关闭时最多 256 tokens；开启时总生成预算（包含推理）依次为 2048/4096/8192，JSON 清单仍保持精简。非思考请求 60 秒超时，思考请求 180 秒超时；不自动重试。
- AI 面板沿用 Liquid Glass 配色；展开助手后直接显示内嵌思考卡片，宽度跟随面板。四档滑杆支持连续拖动、松手吸附和键盘方向键，松手后保存偏好。最高档显示为 Ultra（对应 max），使用紫色渐变与粒子流光，只动画化轨道内的 transform / opacity，不引入动画库或逐帧 JS，也不增加实时背景模糊。面板收起、离开视野或标签页进入后台时停止动画，并遵循系统“减少动态效果 / 降低透明度”设置。
- 使用稀疏短键：`{"r":3,"R":3}` 表示电阻 3、红 LED 3；`G/B/Y/C` 是绿/蓝/黄/透明 LED。不需要的项省略，只有需要提示时附带最多 40 字的 `n`。数量本地验证为 0–999 的整数。
- 页面显示实际输入、输出、思考及服务端缓存命中 token 数。固定 system 提示可供 DeepSeek 自动缓存公共前缀；服务端缓存命中仍是一次接口调用，不能等同于零费用。
- 本地结果缓存默认开启：24 小时过期，最多 50 条，按最近使用淘汰。请求摘要包含接口地址、API Key、完整请求（含模型、强度、system 提示和截断后的需求）；任一项改变均不复用旧结果。缓存仅保存 SHA-256 摘要、已验证清单、说明和时间，不额外保存原始需求或明文 Key。
- 命中本地缓存时不发网络请求，本次新增 token 为 0；“重新生成”绕过缓存并更新结果，“清空缓存”清除内存及持久化缓存。缓存关闭时不读写结果缓存。失败、取消、截断的结果不缓存；存储不可用时降级内存缓存。
- AI 成功回填时，先清空旧选择和所有数量输入，再填本次模型结果，未出现的种类统一归零，最后只重新规划一次。请求失败或取消时保留原选择。
- 降低 `max_tokens` 只是限制最坏输出量，实际费用以 usage 为准。
- 协议参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)。
